# Guides 0.2.1 preview — one running instance

This patch fixes repeated skill or app launches leaving multiple Guides GUI processes running.

## Fixed

- One kernel-managed per-user startup lease is acquired before creating the menu, windows or preferences. Repeated direct launches and copied app bundles exit instead of creating a second GUI; simultaneous patched launches are serialized.
- `guides launch` reuses the running app, including a copy at another location, and reports its PID/path. It preserves measurements, calibration, selected tool and pinned/hidden state. When absent, it launches once and waits a bounded time for startup.
- The skill attaches computer use to the verified running app path. It no longer selects another downloaded/development copy just to attach to Guides.
- Ownership recovers after exit or crash without deleting a stale lock file. Short-lived CLI command processes remain separate from the single persistent GUI instance.

Quit old copies once when installing this update, after saving layouts you want to keep. Quitting discards current measurements and calibration. Already-running older builds are reused rather than terminated; older unfixed binaries cannot gain this guard until replaced. No new app privacy grant, network listener, capture or cross-app inspection is added.

## Download and open

Choose **Guides-0.2.1-macOS-universal.zip**. It contains **Guides.app**, the standalone **guides** launcher, **skills/guides** and **INSTALL.txt**. No Xcode or source checkout is needed.

- Requires **macOS 14 or later**.
- Includes Apple Silicon (`arm64`) and Intel (`x86_64`) code; runtime checks cover Apple Silicon only.
- **Ad hoc signed; not Developer ID signed or Apple notarized.**

Drag Guides.app to Applications and open it. If macOS blocks the first launch and you trust the download, try opening it once, then use **System Settings → Privacy & Security → Open Anyway** and confirm **Open**. [Apple explains this process](https://support.apple.com/en-us/102445). The app does not change security settings or remove quarantine. Managed Macs may block an exception.

From the unzipped folder:

```sh
./guides launch
./guides status
```

Run `launch` again to reuse that PID. Follow **INSTALL.txt** to update an installed launcher and skill. The updated wrapper requires a 0.2.1-or-later selected executable for `launch`; existing measurement commands can still connect to an older running command server. An agent's sandbox may need its normal command-approval path for local Mach messaging.

## Verification and limits

Download **Guides-0.2.1-SHA256SUMS.txt** beside the ZIP, then run:

```sh
shasum -a 256 -c Guides-0.2.1-SHA256SUMS.txt
```

The result should end in **OK**. This verifies integrity and does not replace Developer ID signing or notarization.

Tests cover copied bundles, repeated and simultaneous launches, preserved sessions, crash recovery and reuse of an older running build. Intel runtime, older supported macOS, physical input, mixed displays and full VoiceOver remain unverified. There is no automatic updater. See [validation](https://github.com/parveshh/guides/blob/v0.2.1/TESTING.md) and the [CLI reference](https://github.com/parveshh/guides/blob/v0.2.1/skills/guides/references/cli.md).
